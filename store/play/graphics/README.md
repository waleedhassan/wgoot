# Store graphics

Generated by:

```bash
python store/tool/release.py graphics
```

## What Play requires

| Asset | Spec | Required | File |
| --- | --- | --- | --- |
| App icon | 512×512, **32-bit PNG with an alpha channel**, nothing actually transparent, no rounded corners, ≤1 MB | Yes | `icon-512.png` |
| Feature graphic | 1024×500, PNG or JPEG, no transparency, ≤15 MB | Yes | `feature-graphic-1024x500.png` |
| Phone screenshots | 2–8, PNG or JPEG, 320–3840 px per side, max 2:1 aspect | Yes | `screenshots/phone/` |
| 7-inch tablet | 1–8, same rules | Only for tablet listings | `screenshots/tablet7/` |
| 10-inch tablet | 1–8, same rules | Only for tablet listings | `screenshots/tablet10/` |
| Promo video | A YouTube URL, not a file | No | — |

Play applies its own rounded-corner mask to the icon. Supplying one already
rounded gives you a double-rounded icon, so the generated file is a full square.

## How the generated assets are built

`icon-512.png` is `assets/icon/app_icon.png` resized to 512×512, flattened onto
the palette's dark brown so nothing is see-through, then given a fully opaque
alpha channel — Play's uploader asks for a 32-bit PNG, but an icon with real
transparency in it renders badly once Play applies its own corner mask.

`feature-graphic-1024x500.png` is drawn from the app's own palette and fonts —
the same brown gradient as the app hero, an eight-point star lattice, the app
icon in a gold-ringed badge, and the Arabic title set in IBM Plex Sans Arabic.
Because the title is Arabic, the layout mirrors: icon left, text right-aligned.

Colours, title, subtitle and font all come from the `[graphics]` block in
`store/tool/release.toml`. Change them there and re-run, rather than editing the
PNGs by hand.

Arabic text needs `arabic-reshaper` and `python-bidi` (both in
`store/tool/requirements.txt`). Without them the tool warns and letters render
disconnected and in the wrong order.

## Screenshots

The shipped set is 8 files in `screenshots/phone/`, all **1080×2160**, exactly
2:1, 24-bit PNG with no alpha:

| File | Screen | Source |
| --- | --- | --- |
| `01-home.png` | Home, next prayer and countdown | real device |
| `02-monthly.png` | Full monthly timetable | real device |
| `03-cities.png` | City picker with the Arabic search in use | rendered |
| `04-settings.png` | Settings — method, madhab, alerts | real device |
| `05-adjust.png` | Manual per-prayer adjustment | rendered |
| `06-about.png` | About, the name from the Muwatta | real device |
| `07-home-dark.png` | Home in the dark theme | real device |
| `08-settings-dark.png` | Settings in the dark theme | real device |

Originals are kept in `screenshots/raw/` — `phone-*.png` are the untouched
device captures, `gen-*.png` are the rendered ones.

### Why 1080×2160 and not 1080×2400

Play's rule is that **the longest side may not be more than twice the shortest**.
A modern phone screenshot is 1080×2400, which is 2.22:1 and gets rejected. The
device captures are cropped by 130 px at the top and 110 px at the bottom, which
lands exactly on 2:1 *and* removes the status bar and the gesture pill — system
chrome that does not belong in a store screenshot anyway.

### Re-taking them on a device

Capture on the phone, drop the files into `screenshots/raw/` as
`phone-01.png`, `phone-02.png`, …, then crop each to 2:1 or flatter and strip
the status bar before uploading.

### Re-rendering without a device

[`tool/capture_screenshots_test.dart`](../../../tool/capture_screenshots_test.dart)
renders screens straight from the widget tree — no emulator, no device:

```bash
flutter test tool/capture_screenshots_test.dart
```

It lays the app out at 360×720 logical, captures the repaint boundary at 3×, and
writes 1080×2160 PNGs into `screenshots/raw/gen-*.png`. It loads the real Amiri
and IBM Plex Sans Arabic files plus the Flutter SDK's Material Icons, because
`flutter test` otherwise draws every glyph as a box.

It lives in `tool/` rather than `test/` on purpose, so `flutter test` — and the
release pipeline — do not run it.

Two things to know if you extend it:

- The capture must happen inside `tester.runAsync`. `RenderRepaintBoundary.toImage`
  is real async work, and the test binding's fake clock deadlocks without it.
- Flag emoji do not render. The test environment has no emoji font, and
  registering `NotoColorEmoji.ttf` as an extra font in the same family does not
  make glyph fallback kick in. The city picker screenshot scrolls the country
  header off screen to avoid it. Any screen that must show a flag has to come
  off a real device.

## What gets a listing rejected

Device frames drawn around the screenshot, a status bar from another OS,
marketing copy covering the app, an aspect ratio past 2:1, or a screen the app
does not actually have.
